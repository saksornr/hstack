# Nonconstructive arguments and proof barriers

Separate these claims:

- An object exists.
- A randomly sampled object succeeds with a quantified probability.
- A deterministic algorithm constructs it within stated resources.
- A supplied object can be verified efficiently.

None of these implications should be assumed without an argument. In particular, searching all candidates can turn existence into an algorithm while destroying efficiency.

For a circuit lower-bound proposal, specify the circuit class, size/depth regime, function family, and representation. If discussing natural proofs, identify the exact constructivity, largeness, and usefulness conditions, and the pseudorandomness assumption under which the barrier applies. Do not claim that the barrier rules out all lower-bound proofs or proves the target lower bound false.

For a current-status question, retrieve recent primary literature. The course's 2007 references establish historical coverage, not which problems remain open today. If verification fails, state the last verified result and leave current status unresolved.

Return the proposed proof property, which conditions have been checked, the conditional obstruction if applicable, and possible next work without implying that a suggested escape from the barrier will succeed.
